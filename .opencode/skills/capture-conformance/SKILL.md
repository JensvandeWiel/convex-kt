# Capture Conformance

Use this when you need authoritative wire fixtures for a protocol path, or when
refreshing fixtures after a reviewed upstream change.

Fixtures are **inputs to unit-level conformance tests**. They do not replace the
real-backend integration run required by the three hard rules in `AGENTS.md`.

## Pinned backend

- Backend commit: **`d2ca853`** (`get-convex/convex-backend`).
- Storage: SQLite (no external services).
- Compose file: `conformance/docker-compose.yml` (created in plan step 3 if
  missing).
- Harness: `conformance/harness/` drives the backend with Node and
  `convex-js`.

Never bump the pinned commit inside a fixture-capture change. A bump is its own
reviewed change with a parity note.

## Workflow

1. **Start the backend.**
   `docker compose -f conformance/docker-compose.yml up -d`
   and wait until it reports healthy.
2. **Run the scenario.** Each scenario is a named Node script that logs in,
   opens the WebSocket, and performs exactly one interaction. Drive it with
   `convex-js` so the frames are generated by the reference client.
3. **Record both directions.** Capture every frame in order, with a timestamp
   and direction:
   - `conformance/fixtures/<scenario>/client-to-server.ndjson`
   - `conformance/fixtures/<scenario>/server-to-client.ndjson`
   Raw frames are authoritative; keep a decoded companion only if it helps
   review.
4. **Normalize.** Replace non-deterministic values with typed placeholders and
   document each substitution in `conformance/fixtures/<scenario>/README.md`:
   - session ids, tokens, function ids that vary per run
   - server timestamps
   Keep structural bytes (base64 integer payloads, field ordering) intact.
5. **Pin the scenario.** Record the backend commit and harness commit in the
   fixture README.
6. **Wire into tests.** Point the relevant `convex-core` / `convex-client`
   conformance test at the fixture directory. Fail on the first byte mismatch so
   the diff is obvious.
7. **Tear down.** `docker compose -f conformance/docker-compose.yml down -v`.
8. **Update parity.** Ensure the upstream test this scenario corresponds to is
   `ported` in `parity.yaml` (see the `check-parity` skill).

## Rules

- One scenario, one interaction. A fixture that mixes handshake and mutation
  makes a failed assertion hard to localize.
- Never hand-edit a recorded frame. Re-record it.
- Never commit secrets or live tokens; normalize first.
- If the live backend and the fixture disagree, the fixture is wrong until
  proven otherwise — re-capture from the pinned commit.
